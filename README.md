# scene&diary 0.4.0

scene&diary 是 SillyTavern 与 TauriTavern 的单角色聊天扩展。用剧幕划分经历，在关幕时整理第一人称日记、当前角色画像和可长期使用的事实。

## 安装与连接

在扩展安装器中选择包含 0.4.0 的仓库分支，或把该分支的完整目录放入宿主的第三方扩展目录。仓库包含 `dist/`，正常安装无需本地构建。安装后刷新宿主，在发送区点击剧幕图标。当前交付分支为 `refactor/v0.4.0`，本地试用时可直接使用当前检出。

进入「设置 → API 渠道」，填写 OpenAI 兼容地址、密钥和模型。可先获取模型列表，再进行结构化测试。为日记、成长、事实提取、日记摘要、图谱整理分别分派渠道并保存聊天设置。多个任务可使用同一渠道。0.3.8 的宿主连接需在这里重新配置。

生成使用宿主已有的聊天补全代理。插件收到明确的 `json_schema` 格式拒绝后会试 `json_object`。部分原生 SillyTavern 版本的代理会把上游拒绝简化为 “Bad Request”，这种回复会直接显示为请求失败。Embedding 与 rerank 可分别启用，填写完整端点和模型，浏览器端点须允许相应跨域访问。

## 整理与召回

1. 点「结束这一幕」。日记和事实提取可以并行。日记同时生成正文和摘要，确认日记后才评估成长。可以编辑、保存草稿、单独重试或跳过。日记跳过时也会跳过成长评估。
2. 三项处理完毕后点「确认结束本幕」。下一条真实玩家消息开启新幕。宿主报告保存失败时，当前编辑仍可继续，可重试保存或导出内容。
3. 在「角色成长」直接维护当前画像，或根据全量有效日记生成重整稿并审核。在「日记档案」独立查看、搜索或编辑正文与摘要，正文编辑后可重新确认摘要。旧日记可逐篇或批量补摘要。
4. 在「长期记忆」审核偏好、NPC 关系、重要物品和地点。可编辑、锁定、设置常驻或删除。在图谱中查看有向关系与证据，按需进行全量或增量整理并审核结果。

正常生成时保留当前幕对话，临时插入画像、近期日记正文、相关历史日记摘要和客观事实。历史摘要、近期日记和事实额度分别设置。近期默认全文带入两篇且篇数可改，历史摘要默认约 600 token，事实默认约 1,200 token。查看「诊断」可核对检索耗时、入选项和预算跳过原因。

## 从 0.3.8 升级与回退

首次打开旧聊天时先备份完整聊天，再迁移到 schema 7。旧日记变成可独立编辑的档案条目，已有画像与事实保留。旧偏好可继续召回。旧习惯、承诺、事件、混合物品／地点和未区分角色关系的条目进入「待分类」，保存有效类别后恢复召回。旧无类型关联保存在升级前备份。图谱可以从空图按需整理。

「剧幕工作台 → 备份与恢复」支持导出 v3 内容、导入同一聊天的 v2 或 v3 内容，以及导出升级前的整聊天备份。内容备份包含日记、画像、事实和类型化关系。回退时先导出升级前整聊天备份与当前内容，再安装 0.3.8，将升级前快照的 metadata 和 messages 恢复到旧聊天。用宿主的 JSONL 导入时，首行使用原聊天头并以快照 metadata 恢复 `chat_metadata`，后续每行按顺序写入一条快照消息。保留当前聊天副本，先在导入副本核对。0.4.0 新内容可从 v3 导出查阅。

单角色数据以聊天为单位保存。与 SP·数据库同时启用时，工作台显示冲突并停止 scene&diary 的运行。TauriTavern 可用时使用历史分页、独立缓存和移动布局接口。安装不依赖 Node-only 后端插件。

## 开发与人工验收

`npm ci` 后运行 `npm run build`、`npm test` 与 `git diff --check`。新版基础逻辑用例在 `test/v040.test.mjs` 与 `test/v040-workflows.test.mjs`。其余用例包含旧版迁移基线共用模块及 0.3.8 运行回归，旧界面代码位于测试夹具中。

人工试用时，选择一份 0.3.8 聊天验证迁移和导出。配置并实测渠道，完成一次含失败重试的关幕，编辑旧日记并补摘要，核对成长重整和两路召回。分别在 SillyTavern 浏览器与 TauriTavern 桌面、移动端检查触控、软键盘、保存反馈和刷新后数据。真实模型质量与发布决定由人工确认。
